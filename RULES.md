# Тачка — Правила и реализация

---

## Валюта

- **Валюта:** евро (€)

- Все суммы округлены до десятков и сотен

---

## 1. Концепция и цель

**Пошаговая экономическая настолка на 3–4 человека в Telegram Mini App.**

**Базовый цикл:**
купить авто → отремонтировать дефекты → реализовать (продать банку / отправить в прокат / потаксовать / выставить на гонку)

### Условие победы 🏆

> Побеждает игрок, который **к концу своего хода** имеет на руках **≥ 32 000 €** наличными и **0 активных непогашенных долгов**.

---

## 2. Архитектура и сетевой авторитет

### Сервер — единственный источник правды

- **Сервер** — единственный источник правды. Клиент исключительно отрисовывает игровой стол и передаёт намерения игрока.
- Допустимые намерения: `move`, `buy`, `repair`, `rent`, `race_invite`, `bid`, `pass`

### Запрещено на клиенте ⚠️

- Генерация случайных чисел (`Math.random`)
- Расчёт цен, налогов, начисление штрафов
- Проверка условий победы
- Локальный расчёт таймеров как источника правды

### Валидация

Сервер отклоняет:

- действия вне своей очереди
- повторные клики (debouncing на сервере)
- некорректные шаги
- любые запросы после истечения серверного таймера

| Параметр              | Значение                                                           |
| --------------------- | ------------------------------------------------------------------ |

| **Подключение**       | по ссылке: `t.me/<bot>?startapp=<roomId>`                          |

## 4. Структура хода и перемещение

Один **FSM (конечный автомат)** на комнату.

**Состояния:**
`choose_move` → `resolve_cell` → `end_turn`
(с вложенными подсостояниями: `auction`, `race`, `loan_offer`)

### 4.1 Фаза перемещения (`choose_move`)

- Движение **строго по часовой стрелке**
- **1–2 шага:** бесплатно
- **3–4 шага:** каждый шаг свыше 2 стоит **300 €** (максимальный прыжок за ход — 4 клетки)
- **Вместимость клетки:** максимум **2 фишки**
- **Проходить сквозь** занятую клетку разрешено
- **Остановка на клетке с 2 фишками** запрещена (сервер не даёт выбрать такой шаг)

### 4.2 Фаза действия клетки (`resolve_cell`)

- Игрок выполняет событие клетки
- **Или** вместо действия клетки нажимает альтернативную кнопку **«Такси»**

### 4.3 Фаза завершения хода (`end_turn`)

- Проверка и автоматическое списание подошедших долгов / начисление штрафов
- Снятие кулдауна с машин в прокате (если прошёл полный круг)
- Проверка победы (баланс ≥ 32 000 € и нет долгов)
- Передача хода следующему живому игроку

### ⏱️ Таймеры и дисконнекты


| Событие                                     | Таймер        | Автоход                             |
| ------------------------------------------- | ------------- | ----------------------------------- |
| Обычный ход                                 | **30 секунд** | +1 шаг бесплатно + действие «Такси» |
| Дисконнект (WebSocket разорван &gt; 10 сек) | **5 секунд**  | быстрый автоход                     |


> После **3 пропущенных кругов** подряд игрок объявляется **банкротом**: его машины сгорают в банк, долги аннулируются.

## 5. Игровое поле

**Кольцевой трек.** Состав клеток v1:


| Клетка         | Действие                                                             |
| -------------- | -------------------------------------------------------------------- |
| **Вёдра**      | Покупка дешёвого авто из колоды «Вёдра»                              |
| **Битьё**      | Покупка авто среднего класса с кузовными дефектами                   |
| **Премиум**    | Покупка дорогого авто с высоким чеком ремонта                        |
| **Ретро**      | Покупка эксклюзива (только через открытый аукцион)                   |
| **Автоподбор** | Выбор карты из любой закрытой колоды или выставление лота на аукцион |
| **Автосервис** | Ремонт машин в своём гараже                                          |
| **Скупка**     | Продажа готовых машин банку за фиксированную стоимость               |
| **Прокат**     | Временная сдача готовых авто в аренду банку                          |
| **Гонка**      | Вызов соперника на дуэль с денежным банком                           |


> **Визуал:** клетки различаются контрастными цветами и плоскими глифами (без текстовых надписей на самом треке). Название и контекстные действия отображаются в нижней панели «Действия» при остановке.

## 6. Классы машин и дефекты

**Статусы автомобиля:** `broken` (требует ремонта) → `ready` (готов к эксплуатации/продаже)

### Таблица классов


| Класс       | Цена покупки               | Ремонт                           | Выплата скупки                   |
| ----------- | -------------------------- | -------------------------------- | -------------------------------- |
| **Ведро**   | 400–1 000 €                | Фиксированный, 200–600 €         | Малая маржа (+200–400 €)         |
| **Битьё**   | 1 500–3 500 €              | Бросок d6 в сервисе × множитель  | Средняя маржа (+600–1 200 €)     |
| **Премиум** | 5 000–10 000 €             | Дорогой, риск скрытого дефекта   | Высокая маржа (+2 000–4 000 €)   |
| **Ретро**   | Старт от 8 000 € (аукцион) | Фиксированный, очень дорогой     | Крупная выплата (+4 000–8 000 €) |


### Дефекты

- Тянутся из колоды неисправностей в момент покупки.

### Особые статусы карт

- **«Идеальное состояние»** — карта без дефекта, сразу получает статус `ready`.
- **«Распил»** — неудачная покупка. Скупка выкупает только по цене приобретения (**маржа = 0 €**).

## 7. Правила механик и действий

### 🔧 Автосервис

- Игрок чинит **любое количество машин** в гараже.
- **Оплата:** фиксированная сумма с карты дефекта либо результат броска d6 на сервере (для «Битьё»). Бесплатного ремонта нет, включая стартовое «Ведро».
- Ремонт «Ведра» — **200–600 €**. Со стартовых 1 600 € после починки остаётся минимум 1 000 €.
- После оплаты дефекта машина получает статус `ready`.
- Если денег на ремонт нет, битая машина всё равно может таксовать.

### 💰 Скупка

- Принимает машины со статусом `ready` и `in_rent`. `broken` не принимает.
- «Распил» выкупается по цене покупки, маржа 0 €. Иначе банк платит цену скупки с карты.
- Машина уходит в сброс своей колоды и освобождает слот гаража.

### 🚖 Прокат

> *С защитой от эксплойта бесконечного фарма*

Мгновенная выплата за готовые машины в гараже:


| Класс          | Выплата          |
| -------------- | ---------------- |
| Ведро, Битьё   | +500 € за авто   |
| Премиум        | +1 000 € за авто |
| Ретро          | не сдаётся       |


**Балансировочное правило (Кулдаун):**
При сдаче машина получает статус `in_rent` и счётчик `rentSteps = 0`. Каждый шаг фишки владельца прибавляется к счётчику. Повторная выплата на клетке «Прокат» возможна только при `rentSteps >= 9` (длина круга). Пока счётчик меньше, машина дохода не даёт, но может быть продана в «Скупку». Топтание на «Прокате» внутри одного круга не платит.

### 🚖 Такси

- **Альтернативное действие** на любой клетке хода (вместо свойства клетки).
- Допускается использование машины с **любым статусом** (включая `broken`).
- **Формула дохода:** значение d6 × множитель класса
  - Ведро: ×50 €
  - Битьё: ×100 €
  - Премиум: ×200 €
  - Ретро: такси недоступно.

### 🏁 Гонка

> *С балансом отказа и пулом*

1. Инициатор выбирает соперника, у которого есть **хотя бы 1 машина**.
2. **Ставка инициатора:** не более **50 %** от текущего баланса цели.
3. **Банк** вносит бонусные **1 000 €** в общий призовой фонд.
4. **Выбор цели дуэли:**
   - **Принять вызов:** внести сумму ставки в банк.
   - **Откупиться (техническое поражение):** заплатить инициатору **неустойку 200 €** (гонка отменяется, банк 1 000 € не выплачивается).
5. **Остальные игроки** комнаты имеют **10 секунд**, чтобы нажать «Войти в пул» с аналогичной ставкой.
6. **Исход (v1):** каждый участник бросает чистый d6 на сервере. Модификаторов машины нет — они отложены до колоды «Премиум» и «Ретро». Наибольшее значение забирает весь банк. При ничье лидеров — переброс между ними.

### 🔨 Аукцион

- **Запускается** при выпадении «Ретро», нехватке денег на покупку авто или намеренном выставлении лота через «Автоподбор».
- **Стартовая цена:** номинал карты.
- **Шаг ставки:** +100 €, +500 € или кнопка «Пас».
- **Таймер шага:** 10 секунд. Отсутствие действия = автоматический пас.
- **Побеждает** наивысшая ставка. Если все спасовали на старте — лот возвращается под низ колоды.

### 💸 Займы между игроками (P2P Credit)

1. Любой игрок в свой ход может предложить **P2P-оффер** через контекстное меню: «Сумма X сейчас → возврат Y через N ходов».
2. **N — личные ходы заёмщика**, не круги стола. «Через 2 хода» значит «через 2 моих хода».
3. При согласии заёмщика сумма переводится **моментально**, счётчик `turnsLeft = N`.
4. **Взыскание долга:** счётчик уменьшается на 1 в фазе `end_turn` заёмщика. Когда он доходит до 0, долг списывается в этой же фазе.
5. **Защита кредитора от дефолта:** если у заёмщика не хватает наличных на момент списания:
   - Списываются **все доступные деньги** заёмщика в пользу кредитора.
   - На остаток долга начисляается **штраф +200 € за каждый ход просрочки**.
   - Пока висит непогашенный долг, заёмщик не может покупать новые авто и не может выиграть партию.

## 8. Финансовая модель и точность данных

- Все расчёты денежных балансов на сервере ведутся в **целых евро** (`bigint`). Дробей в правилах нет, `decimal.js` не используется.
- Баланс игрока **никогда не может быть отрицательным** (&lt; 0). Если на транзакцию не хватает средств, действие отклоняется сервером.
- **Победа валидируется сервером** в конце активного хода:

```js
cash ≥ 32000 AND active_loans.length === 0
```

## 9. Сетевой стек и отказоустойчивость

### Стек технологий


| Слой       | Технология                                         |
| ---------- | -------------------------------------------------- |
| **Клиент** | React 19 / Vite / TypeScript / `@telegram-apps/sdk-react` 3.x |
| **Бэкэнд** | Node.js 22+, Socket.IO |


> `@tma.js/sdk-react` снят с поддержки. Автор пакета указывает ставить `@telegram-apps/sdk-react`. Серверная проверка initData — свой HMAC, пакет `@telegram-apps/init-data-node` не обязателен.
>
> Деньги — целые евро, `bigint`. `decimal.js` не используется, пока в правилах нет дробей.

### Аутентификация

- Валидация **Telegram initData** через **HMAC-SHA256** по секретному ключу бота.
- Идентификатор `userId` из тела клиентского запроса **без проверенной подписи не принимается**.

### Хранение стейта и оптимизация I/O

- **Активное состояние комнат** хранится в **RAM**.
- **Запись снимков (snapshots) в SQLite** производится не на каждый клик, а только по завершении **транзакционных фаз хода**: `end_turn`, `auction_end`, `race_end`.
- При перезапуске сервера состояние активных комнат **восстанавливается из последнего снимка SQLite**.

### Хранилище настроек

- **CloudStorage Telegram** и **localStorage** используются строго для **пользовательских UI-настроек клиента** (звук, тема), но **не для данных матча**.

## 10. Требования к UI/UX стола

### Атмосфера 🎨

> «Настольный перекупский покер»

### Запрещено ❌

- Неоновые переливы
- Фиолетовые градиенты

- Тяжеловесные 3D-модели

### Типографика

- **Моноширинные / табличные цифры** (tabular figures) для балансов и таймеров — во избежание дергания вёрстки при обновлении чисел.

### Таймеры

- **Визуальные акцентные цифры** над столом
- 30 секунд (ход) / 10 секунд (аукцион)

### Доступность и анимация

- Переходы **только на смену состояний** (бросок кубика, перемещение фишки)
- Полная поддержка директивы **`prefers-reduced-motion`** с мгновенным переключением позиций
