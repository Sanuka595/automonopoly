# Клиент-серверный контракт и спецификация состояния (API & State)

Документ описывает точный сетевой контракт, модель данных, конечный автомат (FSM) и сокет-события игры **«Тачка»** (Telegram Mini App). Предназначен для фронтенд-разработчиков и UI-агентов.

---

## 1. Модель данных и структуры состояния (State Contract)

Сервер является **единственным источником правды**. Состояние передается клиенту через сокет `room:state`. Все денежные значения на сервере хранятся в целых евро (`bigint`), а при передаче по сети сериализуются в **десятичные строки** (`string`), чтобы исключить потерю точности в JSON.

### 1.1. Денежные суммы (`Euro` на клиенте)
- **Формат в JSON:** строка с целым числом, например `"1600"`, `"500"`, `"32000"`.
- **Правило для UI:** на клиенте не выполнять математику балансов вручную. Для форматирования использовать `Number(val).toLocaleString('ru-RU') + ' €'` (либо моноширинный вывод с CSS `font-variant-numeric: tabular-nums`).

---

### 1.2. Сущность `RoomState` (корневой объект комнаты)

```typescript
export interface RoomState {
  id: string;                               // ID комнаты (например, "room1")
  players: PlayerState[];                   // Список игроков в порядке очереди ходов
  turn: number;                             // Индекс активного игрока в массиве players (0..players.length - 1)
  phase: PhaseState;                        // Текущая фаза FSM
  decks: Record<CarClass, CarState[]>;      // Открытые колоды авто: bucket, beaten, premium, retro
  discards: Record<CarClass, CarState[]>;   // Сброс по каждому классу авто
  pendingLoan?: PendingLoanState | null;    // Активное предложение P2P-займа (если есть)
  timerExpiresAt?: number;                  // Unix timestamp окончания серверного таймера (мс). Используется клиентом для точного отсчета
  updatedAt: number;                        // Unix timestamp последнего изменения (мс)
}
```

### 1.3. Сущность `PlayerState` (игрок за столом)

```typescript
export interface PlayerState {
  id: string;               // Telegram ID (из верифицированного initData)
  name: string;             // Имя игрока (first_name из Telegram)
  cash: string;             // Наличные средства в евро (например, "1600")
  position: number;         // Индекс клетки на треке (0..8)

  loans: LoanState[];       // Активные долги, которые данный игрок ОБЯЗАН вернуть
  missedLaps: number;       // Количество пропущенных кругов подряд (при 3 -> банкротство)
  bankrupt: boolean;        // true, если игрок обанкротился
  turnCount: number;        // Количество завершенных личных ходов игрока
}
```

### 1.4. Сущность `CarState` (автомобиль)

```typescript
export type CarClass = 'bucket' | 'beaten' | 'premium' | 'retro';
export type CarStatus = 'broken' | 'ready' | 'in_rent';

export interface CarState {
  id: string;               // Уникальный ID экземпляра карты
  name?: string;            // Название модели (например, "ВАЗ-2107 «Семёрка»")
  class: CarClass;          // Класс: bucket | beaten | premium | retro
  purchase: string;         // Стоимость покупки в евро
  buyout: string;           // Базовая сумма выкупа банком в Скупке
  defect: DefectState;      // Дефект автомобиля
  status: CarStatus;        // Статус: broken (сломан), ready (готов), in_rent (в прокате)
  taxiMult: string;         // Множитель для такси (евро за 1 очко d6). Для retro = "0"
  rentSteps?: number;       // Счетчик пройденных шагов владельца для кулдауна проката (>= 9 для повторной сдачи)
}
```

### 1.5. Сущность `DefectState` (неисправность)

```typescript
export type DefectState =
  | { kind: 'fixed'; repair: string; desc?: string }         // Фиксированная цена починки
  | { kind: 'roll'; multiplier: string; desc?: string }       // Починка по кубику: d6 * multiplier

  | { kind: 'raspil'; repair?: string; desc?: string };      // Распил: скупка платит только purchase (маржа = 0)
```

### 1.7. Клетки кольцевого трека (`Cell`)

Трек состоит из 9 клеток (индексы 0..8 строго по часовой стрелке):

| Индекс | Идентификатор | Название | Иконка | Описание механики клетки |
|---|---|---|---|---|
| **0** | `buckets` | Вёдра | 🪣 | Покупка авто начального уровня из открытой колоды «Вёдра» |
| **1** | `beaten` | Битьё | 💥 | Покупка авто среднего класса с кузовным дефектом |
| **2** | `premium` | Премиум | 💎 | Покупка авто бизнес/премиум-класса с высоким чеком |
| **3** | `retro` | Ретро | 🏛️ | Остановка мгновенно запускает открытый аукцион на ретро-авто |
| **4** | `picker` | Автоподбор | 🔍 | Покупка авто из любой колоды (0, 1, 2) или выставление Ретро на аукцион |
| **5** | `service` | Автосервис | 🔧 | Починка сломанных машин в гараже или утилизация в чермет (+50 €) |
| **6** | `buyout` | Скупка | 💰 | Продажа готовых авто банку или утилизация сломанного хлама в чермет (+50 €) |
| **7** | `rent` | Прокат | 🏢 | Мгновенная аренда: +500 € (ведро/битьё), +1000 € (премиум). Кулдаун 9 шагов |
| **8** | `race` | Гонка | 🏁 | Дуэль с соперником: банк +1000 €, ставка <= 50% баланса цели, пул для всех |

**Вместимость клеток:** лимита нет. На одной клетке могут стоять все игроки за столом (1–4).

## 2. Машина состояний (FSM) и фазы игры

Состояние фазы определяется полем `room.phase`:

```typescript
export type PhaseState =
  | { name: 'lobby' }
  | { name: 'choose_move' }
  | { name: 'resolve_cell'; cell: Cell }
  | { name: 'auction'; state: AuctionState }
  | { name: 'race'; state: RaceState }
  | { name: 'end_turn' }
  | { name: 'finished'; winnerId: string };
```

### 2.1. Фаза `lobby`
- **Кто активен:** все подключившиеся игроки. Старт запускает хост (`lobby[0]`).
- **Таймер:** отсутствует.
- **Действия:** `auth`, `lobby:start`.

### 2.2. Фаза `choose_move` (Выбор шага перемещения)
- **Кто активен:** только игрок `room.players[room.turn]`.
- **Таймер:** **30 секунд** (при дисконнекте >10с сокращается до 5с).
- **Автоход при таймауте:** минимальный легальный шаг (1..4) + авто-действие «Такси» на первой пригодной машине.
- **Допустимые действия:**
  - `move` (шаги 1, 2, 3 или 4).
  - `loan_offer` (отправка предложения займа в любой момент своего хода).

### 2.3. Фаза `resolve_cell` (Действие на клетке)
- **Кто активен:** только игрок `room.players[room.turn]`.
- **Таймер:** 30 секунд (тот же таймер хода).
- **Допустимые действия (в зависимости от клетки):**
  - Клетки `buckets`, `beaten`, `premium`: `buy`, `taxi`, `pass`.
  - Клетка `picker`: `buy` (любое доступное авто), `start_auction` (ретро), `taxi`, `pass`.
  - Клетка `service`: `repair` (любое количество раз), `scrap` (утилизация хлама в чермет), `taxi`, `pass`.
  - Клетка `buyout`: `buyout` (продажа готового авто), `scrap` (утилизация хлама в чермет), `taxi`, `pass`.
  - Клетка `rent`: `rent`, `taxi`, `pass`.
  - Клетка `race`: `race_invite`, `taxi`, `pass`.
  - В любой момент: `loan_offer`.

**Правило рециклинга колод (Reshuffle):** когда в любой колоде остаётся 0 карт (`decks[class].length === 0`), массив сброса (`discards[class]`) автоматически перемешивается и становится новой открытой колодой данного класса. Сброшенные авто возвращаются со своим исходным дефектом и статусом `broken` (или `ready` для «Идеала»).

### 2.4. Вложенная фаза `auction` (Аукцион)
Запускается при попадании на клетку `retro` или через `start_auction` в автоподборе.

```typescript
export interface AuctionState {
  car: CarState;                     // Разыгрываемый лот
  highestBid: string;                // Текущая наивысшая ставка в евро
  highestBidderId: string | null;    // ID текущего лидера (null на старте)
  currentTurnPlayerId: string;       // Чья очередь делать ставку
  activePlayerIds: string[];         // Игроки, не нажавшие «Пас»
}
```

- **Кто активен:** игрок `auction.state.currentTurnPlayerId`.
- **Таймер:** **10 секунд** на каждый шаг ставки.
- **Авто-действие при таймауте:** автоматический «Пас» (`pass`).
- **Допустимые действия:**
  - `bid` (шаг ставки `+100` или `+500`).
  - `pass` (выход из аукциона).
- **Завершение:** когда все, кроме одного, спасовали. Победитель списывает сумму ставки и получает авто в гараж, после чего ход завершается.

### 2.5. Вложенная фаза `race` (Гонка)

```typescript
export interface RaceState {
  initiatorId: string;               // Кто бросил вызов
  targetId: string;                  // Кого вызвали на дуэль
  stake: string;                     // Сумма ставки в евро
  pool: string;                      // Общий призовой пул (включая бонус банка +1000 €)
  status: 'invitation' | 'pool_entry' | 'rolling';
  participants: string[];            // Все участники, вошедшие в пул
  rolls?: Record<string, number>;    // Выпавшие очки кубиков игроков (id игрока -> очки d6)
  tieContenders?: string[];          // Участники микро-фазы переброса при ничьей
  winnerId?: string;                 // ID победителя гонки
}
```

- **Подстатус `invitation`:**
  - **Кто активен:** только `targetId`.
  - **Таймер:** **10 секунд**.
  - **Авто-действие:** авто-откуп (техническое поражение, штраф 200 €).
  - **Действия:** `race_accept` (внести ставку), `race_forfeit` (откупиться за 200 € инициатору).
- **Подстатус `pool_entry`:**
  - **Кто активен:** все остальные игроки за столом.
  - **Таймер:** **10 секунд**.
  - **Действия:** `race_join_pool` (внести ставку и войти в гонку), `pass` (отказ).
- **Разрешение и микро-фаза переброса (Tie-break):**
  - По истечении таймера пула сервер переходит в статус `rolling` и бросает d6 за всех участников пула.
  - Если зафиксирован **единственный наивысший бросок**, данный участник объявляется победителем (`winnerId`), забирает весь пул, и через 3 секунды ход передается дальше.
  - Если зафиксирована **ничья максимального броска** (2 или более лидеров выбросили одинаковое наибольшее число), сервер сохраняет список претендентов в `tieContenders` и запускает 3-секундную микро-фазу переброса кубиков только между участниками из `tieContenders`. Перебросы повторяются до тех пор, пока не определится ровно один лидер.

### 2.6. Фаза `finished` (Победа)
Игра завершается немедленно при выполнении **любого из двух условий**:
1. **Капитал (финансовая победа):** активный игрок к концу своего хода имеет **наличные >= 32 000 €** и **0 активных долгов** (`loans.length === 0`).
2. **Последний выживший (Elimination):** если из-за банкротств соперников (по 3 пропущенных круга подряд) в игре остался только один не обанкротившийся игрок (`active_non_bankrupt_players.length === 1`), он объявляется победителем досрочно.

После триггера игра завершается, таймеры останавливаются, клиентам выводится экран победителя.

## 3. Каталог сокет-событий (Client -> Server Actions)

### 3.0. Первое подключение и авторизация: `auth`
- **Событие сокета:** `auth`
- **Payload:** `{ initData: string, roomId: string }`
- **Callback (ack):** `(res: { ok: boolean; state?: 'lobby' | 'playing'; error?: string }) => void`
- **Логика:**
  - `initData` — сырая строка запуска из Telegram WebApp (`window.Telegram.WebApp.initData`). В режиме локальной разработки запрашивается через dev-эндпоинт `GET /dev/token?id=1&name=Player1`.
  - Сервер валидирует HMAC-SHA256 подпись по секретному ключу бота.
  - Если игра в комнате ещё не начата, сокет помещается в лобби комнаты (`state: 'lobby'`), и сервер транслирует событие `lobby:update`.
  - Если матч уже запущен, сокет привязывается к существующему игроку (`state: 'playing'`), сбрасывается таймер дисконнекта игрока, и сокет немедленно получает актуальный `room:state`.
- **Ошибки:**
  - `tampered initData` / `invalid signature` — неверная подпись Telegram.
  - `lobby is full` — в лобби уже 4 игрока.

---

### 3.0.1. Старт матча из лобби: `lobby:start`
- **Событие сокета:** `lobby:start`
- **Payload:** отсутствует (пустое сообщение).
- **Callback (ack):** `(res: { ok: boolean; error?: string }) => void`
- **Доступно в:** фазе `lobby`.
- **Ограничения:**
  - Только создатель лобби (первый вошедший игрок `lobby[0]`).
  - Требуется минимум **3 игрока** (`MIN_PLAYERS = 3`, максимум 4).

---

Все последующие игровые намерения передаются через единое событие `intent`:

```typescript
socket.emit('intent', payload, (response: { ok: boolean; error?: string; rolled?: number }) => { ... });
```

### 3.1. Перемещение фишки: `move`
- **Payload:** `{ type: 'move', steps: 1 | 2 | 3 | 4 }`
- **Доступно в:** `phase.name === 'choose_move'`.
- **Стоимость:**
  - 1–2 шага: **0 €**.
  - 3 шага: **300 €**.
  - 4 шага: **600 €**.
- **Ошибки:**
  - `cannot pay the jump` — не хватает наличных на доплату за прыжок >2.
  - `not your turn` — попытка ходить не в свою очередь.

---

### 3.2. Покупка автомобиля: `buy`
- **Payload:** `{ type: 'buy', carId: string }`
- **Доступно в:** `phase.name === 'resolve_cell'` на клетках `buckets`, `beaten`, `premium`, `picker`.
- **Ошибки:**
  - `garage full` — в гараже уже 4 автомобиля (`GARAGE_CAP = 4`).
  - `overdue debt blocks buying` — у игрока есть просроченный долг.
  - `cannot pay purchase` — недостаточно наличных.
  - `car not on offer` — автомобиль не на витрине.

---

### 3.3. Ремонт в автосервисе: `repair`
- **Payload:** `{ type: 'repair', carId: string }`
- **Ack-ответ сервера:** `{ ok: true, rolled: number }` (при успехе возвращает `rolled` — выпавшее значение d6 для дефектов класса «Битьё», либо `0` для фиксированного ремонта).
- **Доступно в:** `phase.name === 'resolve_cell'` на клетке `service`.
- **Логика:** чинит машину в гараже. Если дефект `fixed` — списывает фиксированную сумму; если `roll` (Битьё) — бросает серверный d6 и списывает `d6 * multiplier`; если `raspil` — списывает цену сварки швов (300 €). Статус меняется на `ready`. Не завершает ход автоматически — игрок может отремонтировать несколько машин, после чего нажать `pass`.
- **Ошибки:**
  - `not on service` — игрок не на клетке сервиса.
  - `not broken` — машина не сломана.
  - `cannot pay repair` — не хватает денег на оплату ремонта.

---

### 3.3.1. Утилизация сломанного авто в чермет: `scrap`
- **Payload:** `{ type: 'scrap', carId: string }`
- **Ack-ответ сервера:** `{ ok: true }`
- **Доступно в:** `phase.name === 'resolve_cell'` на клетках `service` (Автосервис) и `buyout` (Скупка).
- **Логика:** предотвращает софтлок при заполнении гаража 4/4 сломанным хламом при отсутствии денег на ремонт. Принимает исключительно авто в статусе `broken`. Авто удаляется из гаража и направляется в сброс `discards[class]`, освобождая слот. Игрок получает символическую компенсацию **50 €**. На клетке `service` не завершает ход автоматически; на клетке `buyout` завершает ход.
- **Ошибки:**
  - `scrap only on service or buyout` — попытка вызова на несоответствующей клетке.
  - `only broken cars can be scrapped` — машина не сломана.
  - `car not in garage` — машины нет в гараже игрока.

---

### 3.4. Продажа в скупку: `buyout`
- **Payload:** `{ type: 'buyout', carId: string }`
- **Ack-ответ сервера:** `{ ok: true }`
- **Доступно в:** `phase.name === 'resolve_cell'` на клетке `buyout`.
- **Логика:** принимает машины со статусом `ready` или `in_rent`. Сломанные (`broken`) отклоняются. За «Распил» выплачивает только цену покупки (`purchase`), за остальные — цену `buyout`. Освобождает слот гаража, завершает ход.
- **Ошибки:**
  - `not sellable` — машина имеет статус `broken`.
  - `car not in garage` — машины нет у игрока.

---

### 3.5. Сдача в прокат: `rent`
- **Payload:** `{ type: 'rent' }`
- **Ack-ответ сервера:** `{ ok: true }`
- **Доступно в:** `phase.name === 'resolve_cell'` на клетке `rent`.
- **Логика:** выплачивает 500 € за каждое готовое Ведро/Битьё и 1000 € за Премиум. Автомобили получают статус `in_rent` со счетчиком `rentSteps: 0`. Ретро в прокат не сдается. Завершает ход.
- **Ошибки:**
  - `nothing to rent` — нет готовых авто или не завершился кулдаун (9 шагов) по сданным ранее.

---

### 3.6. Альтернативное действие: «Такси» (`taxi`)
- **Payload:** `{ type: 'taxi', carId: string }`
- **Ack-ответ сервера:** `{ ok: true, rolled: number }` (возвращает `rolled: 1..6` — выпавшее на сервере очко кубика d6 для анимации).
- **Доступно в:** `phase.name === 'resolve_cell'` на любой клетке хода.
- **Логика:** бросает серверный d6, начисляет `d6 * taxiMult` (Ведро: 50 €, Битьё: 100 €, Премиум: 200 €). Разрешено использовать даже сломанное (`broken`) авто. Ретро таксовать не может. Завершает ход.
- **Ошибки:**
  - `class cannot taxi` — выбрано Ретро.

---

### 3.7. Пропуск действия клетки / Завершение хода: `pass`
- **Payload:** `{ type: 'pass' }`
- **Ack-ответ сервера:** `{ ok: true }`
- **Доступно в:**
  1. `phase.name === 'resolve_cell'` на **любой клетке**: пропуск действия (покупки, ремонта, скупки, проката, гонки) и завершение своего хода без покупок. Вызывает переход в `end_turn` и передачу хода следующему игроку.
  2. `phase.name === 'auction'`: добровольный выход из аукциона (отказ от продолжения торгов за лот).
  3. `phase.name === 'race'` при `status === 'pool_entry'`: отказ стороннего игрока от входа в призовой пул дуэли.
- **Ошибки:**
  - `not your turn` — попытка спасовать вне своей очереди (в обычной фазе).

---

### 3.8. Аукцион: Ставка (`bid`)
- **Payload:** `{ type: 'bid', step: '100' | '500' }`
- **Ack-ответ сервера:** `{ ok: true }`
- **Доступно в:** `phase.name === 'auction'`.
- **Логика:** повышает текущую наивысшую ставку на 100 € или 500 €. Передает очередь следующему участнику и перезапускает таймер 10 секунд.
- **Ошибки:**
  - `not your auction turn` — ставка не в свою очередь.
  - `bid below current` — ставка меньше текущей.
  - `cannot pay bid` — у игрока нет такой суммы наличных.

---

### 3.9. Автоподбор: Выставление Ретро на аукцион (`start_auction`)
- **Payload:** `{ type: 'start_auction' }`
- **Ack-ответ сервера:** `{ ok: true }`
- **Доступно в:** `phase.name === 'resolve_cell'` на клетке `picker`.
- **Логика:** берет верхнюю карту колоды Ретро и открывает аукцион стола со стартовой ценой номинала карты.

---

### 3.10. Гонка: Вызов (`race_invite`), Принятие (`race_accept`), Откуп (`race_forfeit`), Вход в пул (`race_join_pool`)
- **Вызов:** `{ type: 'race_invite', targetId: string, stake: string }`
  - Ставка `stake` не должна превышать 50 % наличных средств цели. У цели должно быть >= 1 авто.
- **Принятие:** `{ type: 'race_accept' }`
  - Цель подтверждает дуэль. Банк добавляет в пул **+1 000 €**. Открывается 10-секундное окно для входа других игроков.
- **Откуп:** `{ type: 'race_forfeit' }`
  - Цель выплачивает неустойку **200 €** инициатору, гонка отменяется, ход завершается.
- **Вход в пул:** `{ type: 'race_join_pool' }`
  - Любой другой игрок вносит аналогичную ставку и становится полноправным претендентом на весь банк.

---

### 3.11. P2P-займы: Оффер (`loan_offer`), Принятие (`loan_accept`), Отклонение (`loan_reject`)
- **Отправка оффера:** `{ type: 'loan_offer', targetId: string, principal: string, due: string, turns: number }`
  - Предлагается активным игроком в свой ход.
  - `principal` <= наличные кредитора.
  - `due` >= `principal`.
  - `turns` >= 1 (личные ходы заёмщика).
  - Создает `room.pendingLoan`.
- **Принятие заёмщиком:** `{ type: 'loan_accept', loanId: string }`
  - Заёмщик может отправить в любой момент получения оффера (даже вне своей очереди).
  - Деньги моментально переводятся заёмщику, в долги заёмщика добавляется объект `Loan`.
- **Отклонение/отзыв:** `{ type: 'loan_reject' }`
  - Может вызвать как заёмщик (отклонить), так и кредитор (отозвать оффер). Очищает `room.pendingLoan`.

## 4. Входящие сокет-события (Server -> Client Events)

### 4.1. `lobby:update`
Приходит при изменении состава лобби до старта партии.
- **Payload:** `LobbyUser[]`

```typescript
interface LobbyUser {
  id: string;        // Telegram user ID
  name: string;      // Имя
  socketId: string;
}
```

### 4.2. `room:state`
Главный широковещательный снимок состояния комнаты. Отправляется после каждого изменения FSM или хода.
- **Payload:** `RoomState` (полный сериализованный объект комнаты из раздела 1.2).

### 4.3. Базовые события подключения
- `connect`: клиент успешно соединился по WebSocket.
- `disconnect`: соединение потеряно (включается серверный таймер 10с ожидания реконнекта).

## 5. Чек-лист интерактивных экранов и модалок для UI

Фронтенд-разработчику необходимо реализовать следующие интерактивные блоки:

### 1. Экран подключения и Лобби
- [ ] Окно ожидания соперников: отображение 3–4 слотов игроков.
- [ ] Индикатор хоста (создателя комнаты с короной 👑).
- [ ] Кнопка «Начать партию» (активна только для хоста при наличии >= 3 игроков).
- [ ] Ссылка/кнопка копирования приглашения (`t.me/<bot>?startapp=<roomId>`).

### 2. Игровой стол и Круговой трек
- [ ] Кольцевая отрисовка 9 клеток с плоскими иконками и контрастными цветами (без текста внутри самих клеток).
- [ ] Отображение цветных фишек игроков на клетках (до 4 фишек на клетку).
- [ ] Подсветка текущей клетки активного игрока.
- [ ] Кнопки перемещения на фазе `choose_move` (+1, +2 бесплатно; +3, +4 с указанием списания -300 € / -600 €).
- [ ] Кнопки перемещения не блокируются из-за чужих фишек на клетке.

### 3. Статус-бар и Таймер
- [ ] Моноширинный таймер хода (30 секунд, акцентная анимация при <5с).
- [ ] Баланс игрока крупными табличными цифрами в евро (`tabular-nums`).
- [ ] Индикатор активного хода: бейдж «Ваш ход» или «Ход игрока X».
- [ ] Индикатор просроченных долгов (штраф +200 €/ход, плашка блокировки покупок).

### 4. Контекстная панель клетки (`resolve_cell`)
- [ ] Клетки покупки (`buckets`, `beaten`, `premium`): карточка верхнего авто из колоды с кнопкой «Купить».
- [ ] Клетка «Автоподбор» (`picker`): выбор из 3 открытых колод или кнопка «Выставить Ретро на аукцион».
- [ ] Клетка «Автосервис» (`service`): список сломанных авто в гараже с кнопками ремонта и ценой починки, а также кнопка «Чермет (+50 €)» для утилизации.
- [ ] Клетка «Скупка» (`buyout`): список готовых авто с кнопками продажи банку и суммой выплаты, а также секция утилизации сломанного хлама в чермет (+50 €).
- [ ] Клетка «Прокат» (`rent`): кнопка сдачи готовых авто с расчетом суммарной выплаты (учитывая кулдаун 9 шагов).
- [ ] Клетка «Гонка» (`race`): выбор соперника из списка, ввод/пресеты ставки (до 50% баланса цели), кнопка «Вызов».
- [ ] Постоянная кнопка быстрого доступа: «Такси» на любом пригодном авто (включая битые).
- [ ] Кнопка завершения хода: «Пас (Конец хода)».

### 5. Модалка / Экран открытого Аукциона
- [ ] Карточка разыгрываемого Ретро-автомобиля.
- [ ] Текущая ставка и лидер аукциона.
- [ ] Таймер шага аукциона: 10 секунд.
- [ ] Кнопки ставки: `+100 €`, `+500 €` и `Пас` (активны только в очередь игрока).

### 6. Модалка / Экран Гонки
- [ ] Уведомление для вызванного игрока: ставка, имя инициатора, кнопки «Принять дуэль» и «Откупиться (200 €)».
- [ ] Экран пула: таймер 10 секунд, кнопка «Войти в пул» для остальных игроков.

### 7. Механика и интерфейс P2P-займов
- [ ] Плашка входящего оффера займа для заёмщика: сумма, возврат, срок, кнопки «Принять» / «Отклонить».
- [ ] Плашка ожидания для кредитора с кнопкой «Отозвать предложение».

- [ ] Статус авто: бейджи `Сломана` (красный), `Готова` (зеленый), `В прокате` (синий со счетчиком шагов X/9).
