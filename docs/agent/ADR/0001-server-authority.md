# ADR 0001 · Сервер — единственный источник правды

Дата: 2026-10 (начало проекта). Статус: принят.

## Контекст

Игра в Telegram Mini App: клиент — JS в WebView противника, его код доступен и
редактируем. Ставки реальные внутриигровые, победа по капиталу 32 000 €
(`server/turn.ts:47`). Любое «доверие» клиенту = читерство за минуту.

## Решение

Клиент шлёт только намерения (`intent`, 17 типов — `server/types.ts:100-117`), сервер
проверяет их гейтом (`assertIntent`, `server/turn.ts:195-247`) и считает правила в
модулях `actions/auction/race/loans/turn`. Клиенту уходит готовый сериализованный
стейт (`serializeRoom`, `server/snapshot.ts:34-37`); деньги клиент только форматирует
(`client/src/components/sheets/formatEuro.ts:1-12`). Случайность — только серверный
`crypto.randomInt` (`server/rng.ts:4`); бросок возвращается в ack (`rolled`) лишь для
анимации (`server/room.ts:231-237`).

## Следствия

- Правила можно менять, не трогая клиент: контракт — интенты и `room:state`.
- Каждый отказ локализован в `RuleError` с текстом, который клиент показывает как есть
  (словарь `client/src/api/present.ts:3-25`).
- Цена — вся логика на сервере и полная перерисовка по каждому событию; оффлайн-игры
  невозможны by design.
- Инвариант «клиент не считает» сегодня охраняется только ревью (см. INVARIANTS.md) —
  на границе сокета нет zod-подобной схемы (см. ветку zcode/t3-zod).
