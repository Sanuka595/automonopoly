# ADR 0002 · Деньги — целые евро в BigInt

Дата: 2026-10. Статус: принят.

## Контекст

RULES.md требует целые евро без дробей; суммы до 32 000 €, операции — вычитание,
сложение, сравнение. Классическая ловушка JS: `0.1 + 0.2` и потеря точности в JSON
на больших числах. decimal.js сочли лишней зависимостью для целых чисел.

## Решение

`type Euro = bigint` (`server/money.ts:2`); фабрика `euro(n)` отказывается от
не-безопасных целых (`server/money.ts:4-7`); единственные операции — `add`/`sub`/`canPay`
(`server/money.ts:21-26`), где `sub` физически не даёт минуса
(`server/money.ts:22-25`). Сеть и БД получают строки: `{"$euro":"1600"}` в SQLite
(`server/snapshot.ts:18-24`), `v.toString()` в `room:state` (`server/snapshot.ts:34-37`).

## Следствия

- Отрицательный баланс невозможен на уровне типов и одной функции — тест
  `server/money.test.ts:5-8`.
- JSON-граница бесплатна только для сериализации сервер → клиент; обратная сторона:
  входящие строки надо приводить к bigint, и **это нигде не сделано** — клиенты шлют
  строки, правила падают/конкатенируют (FINDINGS-1/2/3). Приведение на границе —
  обязательный следующий шаг.
- В клиентах деньги навсегда строки — есть соблазн `Number()`-математики в UI
  (например, в MockTable `client/src/MockTable.tsx:174-195`); для живого стола это
  запрещено (INVARIANTS.md).
