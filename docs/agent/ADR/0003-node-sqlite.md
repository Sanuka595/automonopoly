# ADR 0003 · node:sqlite вместо Redis / внешней БД

Дата: 2026-10. Статус: принят.

## Контекст

Нужен персистент только для одного: восстановить комнату после падения. Матч живёт
минуты, активное состояние — в RAM (`server/room.ts:18-23`). Redis — второй процесс,
операции — лишняя инфраструктура для выходных спринтов.

## Решение

Встроенный `node:sqlite` (`server/snapshot.ts:1`, Node 22+), одна таблица `rooms`
с JSON-блобом состояния (`server/snapshot.ts:4-9`), upsert по id
(`server/snapshot.ts:27-32`). Запись — только на смене хода (`server/room.ts:368-377`),
не на каждый интент: аукционные ставки и входы в пул живут только в RAM до конца хода.

## Следствия

- Ноль зависимостей и ноль операций: прод-зависимости корня — только socket.io
  (`package.json:13-15`).
- Схема «одна колонка JSON» означает: нет SQL-запросов по играм, аналитики и миграций;
  если понадобится история матчей — придётся вторая таблица.
- **Восстановление не подключено**: `loadRooms` (`server/snapshot.ts:39-40`) не вызывается
  в `index.ts` (FINDINGS-5) — инвариант «переживает рестарт» сегодня не выполняется,
  хотя БД-слой готов.
- Падение посреди хода теряет текущий ход — осознанный компромисс против записи
  на каждый клик.
