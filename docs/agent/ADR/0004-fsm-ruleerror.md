# ADR 0004 · Фазовая машина хода и RuleError как единственный отказ

Дата: 2026-10. Статус: принят.

## Контекст

Ход — конвейер `choose_move → resolve_cell → (auction|race) → конец хода`
(`server/types.ts:70-77`). Действия допустимы только в своей фазе и только активному
игроку; отказ должен быть предсказуемым и доходить до игрока текстом, а не разрывом
сокета.

## Решение

Фаза — часть `Room` (иммутабельная комната, каждый интент возвращает новый объект —
`server/actions.ts:19-22`). Один общий гейт до правил: `assertIntent`
(`server/turn.ts:195-247`) проверяет фазу/очередь/набор интентов, затем клеточные
проверки в модулях (`onCell`, `server/actions.ts:13-17`). Все игровые отказы — класс
`RuleError extends Error` (`server/turn.ts:7`); сокет-слой превращает его в ack
`{ok:false,error: err.message}` (`server/room.ts:85-90`), не трогая соединение.
Generic `throw` остался только для внутренних нарушений целостности
(`server/money.ts:5,23`, `server/track.ts:20,26`).

## Следствия

- Правила чистые и синхронные: таймеры, сокеты и БД живут только в RoomManager
  (`server/room.ts`), тестируются без socket.io (32 из 33 тестов — чистые вызовы).
- Текст ошибки — часть контракта: клиент матчит английские строки в словаре
  (`client/src/api/present.ts:3-25`); переименовать текст = сломать UI.
- Транзиентная `end_turn`-фаза есть в типе, но клиент её не видит — сразу
  `advanceTurn` (`server/turn.ts:137-146`); если когда-нибудь понадобится «экран конца
  хода», фазу придётся сделать задерживаемой.
