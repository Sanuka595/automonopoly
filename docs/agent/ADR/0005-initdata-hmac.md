# ADR 0005 · Telegram initData — единственная аутентификация

Дата: 2026-10. Статус: принят.

## Контекст

Игра живёт внутри Telegram Mini App: Telegram передаёт `initData` с подписью бота.
Сессии, пароли, JWT сочли лишними для настолки на 3-4 человека; при этом `userId` из
тела запроса доверять нельзя — его подделывает любой клиент.

## Решение

`verifyInitData` (`server/auth.ts:11-41`) пересчитывает HMAC-SHA256 по канону
Telegram: секрет = HMAC("WebAppData", botToken) (`server/auth.ts:28`), сверка хеша
`timingSafeEqual` (`server/auth.ts:30-32`), свежесть ≤ 3600 с (`server/auth.ts:15,34-37`),
id/имя читаются только из проверенного `user` (`server/auth.ts:38-40`). События `intent`
без пройденного `auth` отклоняются `unauthenticated` (`server/room.ts:81-84`). Пакет
`@telegram-apps/init-data-node` не нужен — 41 строка своего кода (`RULES.md:258`).

## Следствия

- Игрок = его Telegram id, никаких сущностей вне комнаты; нет профилей, балансов
  между партиями, «друзей».
- Без `BOT_TOKEN` в окружении сервер поднимается, но ни один игрок не зайдёт — warning
  при старте (`server/index.ts:19-21`); для dev есть `/dev/token`, подписывающий тестовых
  игроков тем же токеном (`server/index.ts:23-30,52-58`).
- Ссылка-приглашение `t.me/<bot>?startapp=<roomId>` несёт только roomId: войти можно
  любому, у кого есть ссылка и кто прошёл подпись Telegram — права «только свои» нет.
  Проверка подписи тестируется (`server/auth.test.ts`), но срок действия в тестах не покрыт.
