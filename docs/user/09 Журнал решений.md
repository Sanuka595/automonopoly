# 09 Журнал решений 🧭

Шесть решений, на которых стоит проект. Техническая версия с точными ссылками на код — в репозитории, папка `docs/agent/ADR/`.

## 1. Сервер решает всё, клиент только рисует (окт. 2026)

Почему: клиент — JavaScript в чужом WebView, его правит любой продвинутый игрок; экономическая настолка с победой по капиталу не может доверять чей-то телефон. Так, а не иначе: все суммы, кубики и проверка «32 000 €» живут в модулях правил на сервере, клиент шлёт только намерения и получает готовый стол. Альтернатива (клиент считает локально, сервер сверяет) отброшена сразу — двойная реализация правил и вечные споры «кто прав».

## 2. Деньги — целые евро в BigInt (окт. 2026)

Почему: правило «всё в целых евро» позволяет взять `bigint` и не тянуть decimal.js ни на сервер, ни в контракт. Минус запрещён в единственной функции списания — тест на это пишется в первую очередь. Расплата выявилась позже: по сети деньги едут строками, и на границе сокета их надо явно превращать назад в числа — этого пока нет, из-за чего ставки и займы с живого клиента не работают (см. [[07 Если что-то сломалось]]).

## 3. Хранение — встроенный SQLite, одна таблица (окт. 2026)

Почему: сохранять нужно только комнату целиком на границе хода — для этого не нужен Redis ни как «второй процесс в докере». Один файл, одна таблица `rooms`, комната — JSON. Так, а не Redis: матч короткий, состояние живёт в памяти, БД нужна лишь на случай падения. Честная оговорка: подключение восстановления при старте так и не дописано — после рестарта партии теряются.

## 4. Ход — конечный автомат, отказ — RuleError (окт. 2026)

Почему: у хода мало состояний, но много запретов («не твоя очередь», «не та клетка», «нет денег»). Один общий гейт перед правилами + один класс отказа дали два бонуса: правила можно тестировать вообще без сети, а игрок получает читаемый текст «нельзя» вместо разрыва соединения. Альтернатива — коды ошибок-константы — отвергнута: строки уже стали контрактом для UI-словаря.

## 5. Аутентификация — только Telegram initData с HMAC (окт. 2026)

Почему: Mini App и так запускается из Telegram с подписанной строкой; своя система логинов добавила бы пароли, сессии и восстановление. 40 строк своего кода пересчитывают HMAC по канону Telegram, id игрока читается только из проверенной подписи. Альтернатива — готовый пакет — не понадобился; расплата: без валидного бот-токена сервер поднимается, но в него никого не пускает.

## 6. Монорепо без сборщика на сервере (окт. 2026)

Почему: сервер — пара тысяч строк и единственная зависимость socket.io; Node 22+ исполняет TypeScript напрямую, поэтому сборки сервера просто нет — `node --experimental-strip-types`. Клиенту сборщик нужен (React, Tailwind) — там Vite. Так, а не два репозитория: контракт (типы событий и состояний) живёт по обе стороны, в одном коммите меняешь обе. Расплата: импорты с явным `.ts` и запрет TS-магии (enum/декораторов) на сервере.
